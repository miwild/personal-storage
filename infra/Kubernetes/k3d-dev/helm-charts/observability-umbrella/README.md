# k3d-dev Observability Stack

This Helm chart wraps the upstream [`kube-prometheus-stack`](https://github.com/prometheus-community/helm-charts/tree/main/charts/kube-prometheus-stack) to provide Grafana, Prometheus, Alertmanager, and node metrics collection for the local k3d development environment.

It is pinned to chart version `92.11.0` (appVersion `v0.94.1`) and intended for Kubernetes v1.35 (k3s/k3d default in the dev cluster).

## Components

The stack includes:

- **Prometheus Operator** - manages Prometheus and Alertmanager instances
- **Prometheus** - metrics collection and querying
- **Alertmanager** - alert routing and silencing
- **Grafana** - dashboards and visualization
- **kube-state-metrics** - Kubernetes object metrics
- **node-exporter** - node-level metrics

## Service Names and Ports

After installing this chart with release name `kube-prometheus-stack`, the following Services are created in the `platform-observability` namespace:

| Component      | Service Name                          | Port  | Notes                            |
|----------------|---------------------------------------|-------|----------------------------------|
| Grafana        | `kube-prometheus-stack-grafana`      | 80    | → container port 3000            |
| Prometheus     | `kube-prometheus-stack-prometheus`    | 9090  |                                  |
| Alertmanager   | `kube-prometheus-stack-alertmanager`  | 9093  |                                  |
| kube-state-metrics | `kube-prometheus-stack-kube-state-metrics` | 8080 |                           |
| node-exporter  | `kube-prometheus-stack-prometheus-node-exporter` | 9100 |                        |

These names are referenced by the Traefik IngressRoutes in `../templates/traefik/portfolio-ingress.yaml`.

## Local Access

### Via Traefik (preferred)

The portfolio IngressRoute already defines:

- `https://grafana.local.example.com/` → `kube-prometheus-stack-grafana:80`
- `https://prometheus.local.example.com/` → `kube-prometheus-stack-prometheus:9090`

No changes are needed to the IngressRoute as long as the Service names and ports above are used.

### Via port-forward

For direct access bypassing Traefik:

```bash
# Grafana
kubectl -n platform-observability port-forward svc/kube-prometheus-stack-grafana 3000:80

# Prometheus
kubectl -n platform-observability port-forward svc/kube-prometheus-stack-prometheus 9090:9090
```

Then visit http://localhost:3000/ or http://localhost:9090/

## Admin Credentials

### Grafana

The admin password is auto-generated by the chart. Retrieve it with:

```bash
kubectl -n platform-observability get secret kube-prometheus-stack-grafana -o jsonpath='{.data.admin-password}' | base64 -d
```

To use fixed credentials instead:

1. Create a Secret in `platform-observability`:

   ```bash
   kubectl -n platform-observability create secret generic grafana-admin \
     --from-literal=admin-user=admin \
     --from-literal=admin-password=somepassword
   ```

2. Uncomment and set in `values.yaml`:

   ```yaml
   kube-prometheus-stack:
     grafana:
       existingSecret: grafana-admin
   ```

3. Upgrade the release.

## Storage

The Prometheus TSDB and Alertmanager state use PersistentVolumeClaims on the `local-path` StorageClass (k3s default). They survive Pod restarts but are deleted with the release.

Grafana uses an emptyDir volume - dashboards created through the UI are lost when the Pod restarts. Manually created dashboards should be exported and imported as JSON.

## Validation Commands

Before installing, validate the chart with:

```bash
# From this directory
helm dependency build .

helm lint .

# Template the release to inspect the generated resources
helm template kube-prometheus-stack . -n platform-observability --kube-version 1.35.5
```

## Installing in k3d-dev

Apply the platform namespaces first (admin-managed):

```bash
kubectl apply -f ../templates/namespaces/platform-namespaces.yaml
```

Then install the chart:

```bash
helm dependency build .

helm upgrade --install kube-prometheus-stack . \
  -n platform-observability \
  --create-namespace
```

## Uninstalling

To remove the stack:

```bash
helm uninstall kube-prometheus-stack -n platform-observability
```

The PersistentVolumeClaims for Prometheus and Alertmanager must be deleted separately if desired:

```bash
kubectl -n platform-observability delete pvc -l app.kubernetes.io/instance=kube-prometheus-stack
```

## Known Limitations

### Control Plane Metrics

In k3s, the control plane components (etcd, kube-scheduler, kube-controller-manager, kube-proxy) bind their metrics endpoints to localhost only. Their corresponding ServiceMonitors in this chart produce permanently DOWN targets.

They are disabled by default in `values.yaml`:

- `kubeEtcd.enabled: false`
- `kubeScheduler.enabled: false`
- `kubeControllerManager.enabled: false`
- `kubeProxy.enabled: false`

CoreDNS metrics work (runs as Deployment) and are enabled.

### ServiceMonitor Discovery

By default (`serviceMonitorSelectorNilUsesHelmValues: true`), Prometheus discovers ServiceMonitors only in its own namespace (`platform-observability`) or those labeled with:

```yaml
app.kubernetes.io/instance: kube-prometheus-stack
```

To scrape metrics from applications in other namespaces (e.g., `platform-nextcloud`):

1. Deploy a ServiceMonitor in that namespace.
2. Add the label:

   ```yaml
   metadata:
     labels:
       app.kubernetes.io/instance: kube-prometheus-stack
   ```

Alternatively, to discover all ServiceMonitors cluster-wide, override in `values.yaml`:

```yaml
kube-prometheus-stack:
  prometheus:
    prometheusSpec:
      serviceMonitorSelector: {}
```

This lowers isolation but removes the labeling requirement.
